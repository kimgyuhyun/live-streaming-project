# 확정 사양

> 원본: `docs/plan.html` (기획 통합본 + 2차 검토 보완 + 로컬 인프라 검증 결과)
> 상태: **확정** (2026-11-20). 기획서에 없던 숫자·규칙은 초안에서 제안한 값을 사용자가 그대로 확정했다.

이 문서는 **무엇을 만드는가**(제품 규칙)만 적는다. 어떤 구조로, 왜 그렇게 만드는지는 `docs/result/prd/{도메인}.md`에 둔다.

범위는 기획서의 **A(기본 골격)**만이다. B(추후 확장)는 맨 아래 "이번에 만들지 않는 것"에 있다.

---

## 1. 사용자와 권한

| 역할 | 누구 | 할 수 있는 것 |
| --- | --- | --- |
| 비로그인 시청자 | 로그인하지 않은 방문자 | 방송 목록·검색·채널 페이지 보기, 방송 시청, 채팅 읽기 |
| 회원 | 이메일로 가입한 사람 | 비로그인 시청자의 모든 것 + 채팅 쓰기, 즐겨찾기, 포인트 충전·후원, 스트리머 신청 |
| 스트리머 | 운영자가 승인한 회원 | 회원의 모든 것 + 채널 관리, 스트림 키 발급·재발급, 방송 송출, 적립 포인트 조회 |
| 운영자 | 이 서비스를 운영하는 본인 | 스트리머 신청 승인·거절 |

- 운영자 화면은 만들지 않는다(관리자 페이지는 B). 운영자는 화면 없는 API로 승인한다.
- 운영자 계정은 가입으로 만들지 않고, 배포할 때 미리 넣어 둔다.

## 2. 회원·계정

### 가입

- 이메일, 비밀번호, 닉네임으로 가입한다.
- 이메일 인증(메일 발송)은 하지 않는다. 형식 검사와 중복 검사만 한다.
- 이메일은 대소문자를 구분하지 않는다(`A@b.com`과 `a@b.com`은 같은 계정).
- 비밀번호: 8~64자, 영문과 숫자를 각각 하나 이상 포함. 쓸 수 있는 문자는 영문·숫자·특수문자(공백을 뺀 ASCII)뿐이다. (#1 보안 점검에서 추가 — 한글처럼 여러 바이트인 문자로 64자를 채우면 BCrypt 한도 72바이트를 넘어 오류가 났다)
- 닉네임: 2~12자, 한글·영문·숫자만, 다른 회원과 겹칠 수 없다. 채팅에 이 이름이 보인다.

### 로그인·로그아웃

- 이메일과 비밀번호로 로그인한다. 로그인 상태는 세션(서버가 로그인 상태를 기억하고 브라우저에는 쿠키로 식별자만 주는 방식)으로 유지한다.
- 마지막 요청 후 **7일** 동안 요청이 없으면 로그인이 풀린다.
- 로그아웃하면 즉시 로그인이 풀린다.
- 로그인 실패 시 "이메일 또는 비밀번호가 맞지 않습니다" 하나로 알린다. 이메일이 없는지 비밀번호가 틀렸는지 구분해서 알려 주지 않는다.

### 로그인 시도 제한

- **같은 이메일로 5번 연속 실패하면 그 이메일은 15분 동안 로그인할 수 없다.** 성공하면 실패 횟수가 초기화된다.
- 마지막 실패 후 15분 동안 실패가 없으면 실패 횟수는 0으로 돌아간다. 차단은 5번째 실패 순간부터 15분이다.
- **같은 IP에서 15분 안에 20번 실패하면 그 IP는 15분 동안 로그인할 수 없다.** 여러 이메일을 돌려 가며 시도하는 것을 막는다.
- 차단 중에는 비밀번호가 맞아도 로그인되지 않고, 남은 시간을 알려 준다.
- IP는 앞단 프록시가 넘겨준 실제 사용자 IP를 쓴다.

### 계정 정보

- 내 이메일·닉네임·역할(회원/스트리머)을 볼 수 있다.
- 닉네임을 바꿀 수 있다(가입 규칙과 같음).
- 현재 비밀번호를 확인한 뒤 비밀번호를 바꿀 수 있다. 바꾸면 다른 기기의 로그인도 풀린다.
- 비밀번호 찾기(재설정 메일)와 회원 탈퇴는 하지 않는다.

## 3. 스트리머·채널

### 스트리머 신청과 승인

- 회원은 스트리머 신청을 한 번 할 수 있다. 신청 상태: **대기 → 승인 / 거절**.
- 거절된 회원은 다시 신청할 수 있다. 대기 중에는 다시 신청할 수 없다.
- 운영자가 승인하면 그 회원은 스트리머가 되고, **채널이 하나 만들어진다.** 스트림 키는 스트리머가 스튜디오에서 처음 발급한다.
- 승인되면 그 회원은 로그아웃된다. 다시 로그인하면 스트리머로 쓸 수 있다.
- 스트리머 권한을 다시 빼는 기능은 없다.

### 채널

- 스트리머 한 명당 채널은 **하나**다.
- 채널 정보: 채널 이름(2~20자, 처음에는 닉네임), 소개(0~200자). 스트리머가 바꿀 수 있다.
- 채널 페이지에 보이는 것: 채널 이름, 소개, 방송 상태(방송 중/오프라인), 방송 중이면 방송 제목·시청자 수·플레이어·채팅.
- 데모 채널에는 "데모 채널" 표시가 붙는다.

## 4. 스튜디오 (스트리머 전용)

### 스트림 키

- 스트림 키는 스트리머마다 하나다. 추측할 수 없는 무작위 문자열이다.
- **키 전체는 발급·재발급 직후 한 번만 보여 준다.** 그 뒤에는 앞 4자리만 보여 주고 나머지는 가린다. 키를 잃어버리면 재발급한다.
- **재발급하면 이전 키는 즉시 쓸 수 없다.** 이전 키로 송출 중이었다면 그 송출은 끊기고, 송출 프로그램이 이전 키로 다시 접속해도 거부된다.

### OBS 연결 안내

- 스튜디오에 OBS 설정값을 보여 준다: 서버 주소 `rtmp://{서버}/live`, 스트림 키 칸에 넣을 값 `{채널ID}?key={스트림키}`.
- 키프레임 간격을 1~2초로 설정하라는 안내를 함께 보여 준다.

### 방송 제목과 상태

- 방송 제목: 1~50자. 방송 전에 미리 정해 둘 수 있고, 방송 중에도 바꿀 수 있다. 정하지 않았으면 "{채널 이름}의 방송"이다.
- 스튜디오에서 지금 송출이 들어오고 있는지(연결 상태)를 볼 수 있다.

## 5. 방송 송출과 시청

### 방송

- **방송** = 송출이 시작돼서 끝날 때까지 한 번. 송출이 들어오면 방송이 시작되고, 끊기면 방송이 끝난다.
- 송출 시작 때 스트림 키를 확인한다. 키가 틀리거나, 스트리머가 아니거나, 키가 없으면 송출을 거부한다.
- 한 채널에서 동시에 방송은 하나뿐이다. 이미 방송 중인데 같은 채널로 또 송출이 들어오면 거부한다.

### 시청

- 로그인하지 않아도 시청할 수 있다.
- 방송이 시작된 뒤 약 2~4초 늦게 화면에 나온다(저지연 HLS(영상을 짧은 조각으로 나눠 HTTP로 보내는 방식. 조각을 더 잘게 나눠 지연을 줄인 변형)).
- 화질: 원본(OBS가 보낸 그대로) 하나. 720p를 추가로 줄지는 미해결 항목 1을 본다.
- **화질 자동 전환은 하지 않는다.** (로컬 검증에서 전환할 때마다 재생이 멈추고 지연이 쌓였다)
- 방송이 끝나면 플레이어 자리에 "방송이 종료되었습니다"를 보여 준다.

### 썸네일

- 방송 중인 화면에서 자동으로 만든다. 방송 시작 직후 한 장, 그 뒤 **2분마다** 새로 만든다.
- 방송이 끝나면 오프라인 기본 이미지를 보여 준다. 지난 썸네일은 남기지 않는다.

## 6. 채팅

- 방송마다 채팅방이 하나다. **방송 중일 때만** 채팅을 쓸 수 있다.
- 비로그인 시청자는 **읽기만** 한다. 쓰려면 로그인해야 한다.
- 메시지: 1~200자. 앞뒤 공백을 빼고 비어 있으면 보내지 않는다.
- 채팅에 보이는 것: 닉네임, 메시지. 스트리머 본인 메시지에는 스트리머 표시가 붙는다.
- 채팅 기록은 저장하지 않는다. 채팅방에 들어온 뒤의 메시지만 보인다.
- 데모 방송에 채팅 봇을 붙이면, 봇 메시지에 봇 표시가 붙는다.

### 도배 제한

- **한 회원은 5초 안에 메시지를 5개까지 보낼 수 있다.** 넘으면 그 메시지는 보내지지 않고, 본인에게만 "잠시 후 다시 보내 주세요"가 보인다.

## 7. 시청자 활동

### 동시 시청자 수

- 지금 그 방송을 보고 있는 사람 수. **비로그인 시청자도 센다.**
- 채널 페이지와 방송 목록에 보인다. 몇 초 늦게 반영될 수 있다(최대 10초).
- 한 사람이 탭 두 개로 보면 2로 세도 된다.
- 세는 방법은 미해결 항목 2를 본다.

### 즐겨찾기

- 회원은 채널을 즐겨찾기에 넣고 뺄 수 있다. 자기 채널도 넣을 수 있다.
- "즐겨찾기" 목록: 방송 중인 채널이 먼저, 그다음 오프라인 채널.
- 채널 페이지에 즐겨찾기한 회원 수를 보여 준다.

## 8. 후원

실제 돈은 오가지 않는다. 가상 재화 **포인트**로만 한다.

### 포인트 충전

- 회원은 포인트를 충전할 수 있다. 결제는 없고, 누르면 바로 들어온다.
- 한 번에 1,000~100,000 포인트, 1,000 단위.
- 보유 포인트는 1,000,000을 넘을 수 없다. 넘게 되는 충전은 거부한다.

### 후원

- 회원은 **방송 중인** 채널에 포인트를 후원할 수 있다.
- 한 번에 100 포인트 이상, 100 단위, 보유 포인트 이하.
- 메시지를 0~100자 붙일 수 있다.
- 자기 채널에는 후원할 수 없다.
- 후원하면 후원자의 포인트가 줄고, 같은 양이 스트리머의 **적립 포인트**로 들어간다. 수수료는 없다.
- 후원이 성공하면 그 방송 채팅에 후원 알림(닉네임, 포인트, 메시지)이 뜬다.

### 지켜야 할 것

- **보유 포인트는 절대 0보다 작아지지 않는다.** 같은 회원이 동시에 여러 번 후원해도 그렇다.
- **같은 후원 요청이 두 번 들어와도(버튼을 두 번 누르거나 응답이 늦어 다시 보낸 경우) 한 번만 처리된다.**
- 모든 충전·후원·적립은 **원장**(포인트가 움직인 기록을 한 줄씩 쌓는 장부)에 남는다. 보유 포인트와 적립 포인트는 언제나 원장의 합과 같다.

### 조회

- 회원: 내 보유 포인트, 내 포인트 내역(충전·후원, 최근순).
- 스트리머: 내 적립 포인트, 받은 후원 내역(최근순).
- 적립 포인트를 꺼내 쓰는 기능(정산·출금)은 없다.

## 9. 탐색·검색

### 방송 목록

- 지금 방송 중인 방송만 보인다.
- 정렬: **시청자 수가 많은 순.** 같으면 먼저 시작한 순.
- 각 항목: 썸네일, 방송 제목, 채널 이름, 시청자 수.
- 한 번에 20개씩 더 불러온다.

### 검색

- 검색어 2~30자, 앞뒤 공백 제외. 대소문자를 구분하지 않는다.
- 검색 결과는 두 묶음이다.
  - **방송 중:** 방송 제목 또는 채널 이름에 검색어가 들어간 방송. 정렬은 방송 목록과 같다.
  - **채널:** 채널 이름에 검색어가 들어간 채널(오프라인 포함).

## 10. 데모 방송

- 테스트 스트리머 계정 3~5개가 서버 안에서 영상 파일을 반복 송출한다. 개수는 서버 CPU 측정 뒤에 정한다.
- 데모 방송도 실제 방송과 같은 경로(키 확인 → 수신 → 시청)를 탄다. 목록·시청자 수·썸네일·채팅이 똑같이 동작한다.
- 데모 채널에는 "데모 채널" 표시가 붙는다. 영상은 직접 만들었거나 녹화한 것, 또는 출처를 표기한 공개 영상(CC BY)만 쓴다(#14 — ffmpeg로 생성한 영상도 직접 만든 것이다).

## 11. 보안

- 비밀번호는 되돌릴 수 없는 해시로만 저장한다.
- 스트림 키는 로그·API 응답·화면에 전체가 나오지 않는다(발급·재발급 직후 한 번 제외).
- 역할에 맞지 않는 요청은 거부한다. 남의 채널·키·포인트 내역은 보거나 바꿀 수 없다.

## 용어 정의

| 용어 | 뜻 | 쓰지 않는 말 |
| --- | --- | --- |
| 회원 | 이메일로 가입한 사람 | 유저, 사용자(코드에서) |
| 비로그인 시청자 | 로그인하지 않은 방문자 | 게스트, 익명 |
| 스트리머 | 운영자가 승인한 회원 | BJ, 크리에이터 |
| 운영자 | 스트리머 신청을 승인하는 사람(본인) | 관리자(관리자 페이지와 헷갈림) |
| 스트리머 신청 | 회원이 스트리머가 되겠다고 요청한 것. 대기·승인·거절 | 권한 요청 |
| 채널 | 스트리머마다 하나 있는 방송 공간 | 방, 룸 |
| 방송 | 송출이 시작돼서 끝날 때까지 한 번 | 라이브, 스트림(방송 뜻으로) |
| 송출 | OBS 등에서 서버로 영상을 보내는 것 | 업로드, 퍼블리시(문서에서) |
| 시청 | 웹에서 방송을 보는 것 | 재생(사용자 행동을 말할 때) |

## 원본 대비 변경 사항

| 항목 | 원본 | 확정 | 이유 |
| --- | --- | --- | --- |
| 후원 | B(추후 확장) | A, 가상 포인트로만 | 같은 잔액 동시 차감 문제를 다루는 유일한 기능. 실결제는 기존 포트폴리오에서 다뤘다 |
| 스트리머 권한 | 미결정 | 운영자 승인제 | 아무나 송출하면 불법 영상으로 서버 계정이 정지될 위험. 2코어로 동시 방송을 많이 감당 못 함 |
| 비로그인 채팅 | 미결정 | 읽기만 | 쓰기를 허용하면 도배를 막을 기준이 없다 |
| 로그인 시도 제한·도배 제한 | 로그인 제한 B, 도배 제한 없음 | 둘 다 A | 공개 서버라 처음부터 필요 |
| 화질 | 1080p 원본 + 720p, 자동 전환 | 원본 하나, 자동 전환 없음. 720p는 미해결 | 로컬 검증: 두 화질을 묶으면 전환 때마다 재생이 멈추고 지연이 2.1초 → 5.7초로 쌓였다 |
| 운영자 | 언급 없음(관리자 페이지는 B) | 화면 없는 승인 API를 쓰는 운영자 역할 | 승인제를 하려면 누군가 승인해야 한다 |
| 일정 | 1주차에 서버 배포 | 로컬에서 먼저 완성, 배포는 3주 후반 | 로컬에서 어느 정도 완성한 뒤 CI/CD와 배포를 붙인다 |

## 미해결 항목

| # | 항목 | 정할 때 | 현재 상태 |
| --- | --- | --- | --- |
| 1 | 720p 제공 여부 | 서버 배포 후 CPU 측정 | (a) 수동 화질 선택(고르면 그 화질로 다시 불러오기) 또는 (b) 제공 안 함 |
| 2 | 동시 시청자 수를 세는 방법 | PRD(시청자 활동) ADR | 채팅 WebSocket 연결 수 vs MediaMTX 시청 세션 수 |
| 3 | 데모 방송 개수 | 서버 배포 후 CPU 측정 | 3~5개 |

기술 쪽 미해결(제품 규칙이 아니라 PRD에서 정함): Flyway 경고 처리, 스트림 키 저장 방식, 포인트 동시성 방어 방식, 같은 후원 요청 판별 방식.

## 이번에 만들지 않는 것

기획서 B(추후 확장) 그대로다: 소셜 로그인, VOD(다시 보기), 수동 썸네일 업로드, 알림(방송 시작 알림·알림함·푸시), 관리자 페이지와 신고 처리, 상세 감사 로그, CDN, 실결제 충전·유료 구독·정산, 광고.

확정하면서 더 뺀 것: 이메일 인증, 비밀번호 찾기, 회원 탈퇴, 스트리머 권한 회수, 채팅 기록 저장·채팅 관리(메시지 삭제·사용자 차단), 적립 포인트 출금.
